# PyHydroGeophysX Software Architecture for SoftwareX Paper

## Overview

PyHydroGeophysX is a modular Python platform for integrating hydrological models with geophysical measurements. The architecture enables bidirectional workflows between hydrological modeling and geophysical monitoring domains.

## Module Descriptions

| Module | Purpose | Key Capabilities |
|--------|---------|------------------|
| **model_output** | Hydrological model interface | MODFLOW/ParFlow water content, saturation, porosity |
| **data_processing** | Field data handling | ERT data loading, quality control, format export |
| **core** | Spatial utilities | 2D/3D mesh creation, interpolation, kriging |
| **petrophysics** | Property transformation | Resistivity models (Waxman-Smits), velocity models (DEM, Hertz-Mindlin) |
| **forward** | Forward simulation | ERT, Seismic, TDEM synthetic data generation |
| **inversion** | Inverse modeling | Single-time, time-lapse, structure-constrained inversion |
| **solvers** | Numerical computation | Linear solvers with optional GPU acceleration |
| **Hydro_modular** | HM → GM workflow | Direct hydrological to geophysical conversion |
| **Geophy_modular** | GM → HM workflow | Geophysical interpretation, structure integration, uncertainty quantification |

## Data Flow Patterns

**Forward Direction (HM → GM):**
```
Hydro Model → model_output → petrophysics → forward → Synthetic Geophysical Data
```

**Inverse Direction (GM → HM):**
```
Field Data → data_processing → core (mesh) → inversion → Geophy_modular → Hydrological Properties
```

**Coupled Workflow:**
```
Hydro Model ↔ petrophysics ↔ forward ↔ inversion ↔ Comparison/Validation
```

## External Dependencies

| Library | Role |
|---------|------|
| PyGIMLi | ERT/Seismic forward modeling and inversion |
| SimPEG | TDEM forward modeling and inversion |
| FloPy | MODFLOW model output interface |
| PFTools | ParFlow model output interface |
| NumPy/SciPy | Numerical operations |
| ResIPy | Field ERT data loading (optional) |
| CuPy | GPU acceleration (optional) |

## Design Principles

- **Modular**: Independent modules with clear interfaces
- **Extensible**: New hydrological models or geophysical methods can be added
- **Interoperable**: Built on established open-source geophysical libraries

# PyHydroGeophysX Software Architecture

## 1. Architectural Overview

PyHydroGeophysX employs a modular, layered architecture designed to facilitate bidirectional integration between hydrological models and geophysical measurements. The software is organized into seven functional modules distributed across four logical layers: Data I/O, Core Processing, Geophysical Modeling, and Integration (Figure X). This architecture enables flexible workflows while maintaining clear separation of concerns between different functional components.

The design philosophy prioritizes extensibility and interoperability. Each module exposes well-defined interfaces, allowing new hydrological model formats or geophysical methods to be incorporated without modifications to existing code. The platform leverages established open-source libraries—PyGIMLi for electrical and seismic methods, SimPEG for electromagnetic methods, FloPy for MODFLOW, and PFTools for ParFlow—ensuring compatibility with community standards and benefiting from ongoing development in these foundational packages.

## 2. Module Architecture

### 2.1 Data I/O Layer

The Data I/O layer provides interfaces for importing data from both hydrological models and geophysical field instruments.

**model_output**: This module handles the extraction of state variables from numerical hydrological models. For MODFLOW simulations, the module interfaces with FloPy to read binary output files containing head distributions, which are subsequently converted to water content and saturation fields using user-specified storage parameters. For ParFlow simulations, the module utilizes PFTools to access pressure and saturation outputs from the distributed binary file format. The module implements an abstract base class (`HydroModelOutput`) that defines a consistent interface for loading single timesteps or time ranges, enabling straightforward extension to additional hydrological modeling platforms.

**data_processing**: This module manages the import and quality control of geophysical field data. The current implementation focuses on electrical resistivity tomography (ERT) data, supporting multiple instrument formats including Syscal, ABEM, Sting, and E4D through integration with the ResIPy library. The module provides automated quality control procedures including reciprocal error analysis, contact resistance checking, and outlier detection. Processed data are exported in standardized formats compatible with the inversion module.

### 2.2 Core Processing Layer

The Core Processing layer provides fundamental computational utilities required by both forward and inverse modeling workflows.

**core**: This module implements spatial operations including mesh generation, coordinate interpolation, and geostatistical analysis. Two-dimensional mesh generation supports the creation of unstructured triangular meshes with topographic boundaries and internal layer constraints. Three-dimensional mesh generation utilizes GMSH for tetrahedral discretization with electrode positioning. The interpolation submodule provides tools for mapping hydrological model outputs (typically on structured grids) onto geophysical meshes (typically unstructured). For three-dimensional applications, the module includes kriging functionality based on GSTools for spatial estimation of properties between measurement profiles.

**petrophysics**: This module implements constitutive relationships that transform between hydrological state variables and geophysical properties. For electrical methods, the module provides the Waxman-Smits model relating water content, porosity, and pore fluid conductivity to bulk electrical resistivity, with provisions for surface conductivity effects in clay-bearing formations. For seismic methods, the module implements rock physics models including the Voigt-Reuss-Hill averaging scheme for mineral mixtures, the Differential Effective Medium (DEM) theory for cracked media, and the Hertz-Mindlin contact theory with Hashin-Shtrikman bounds for granular materials. These petrophysical transforms operate bidirectionally, supporting both forward prediction of geophysical responses from hydrological states and inverse estimation of hydrological properties from geophysical measurements.

**solvers**: This module provides linear algebra solvers optimized for geophysical inverse problems. Implemented algorithms include Conjugate Gradient Least Squares (CGLS), LSQR, and regularized variants (RRLS). The module supports optional GPU acceleration through CuPy for large-scale three-dimensional problems, with automatic fallback to CPU computation when GPU resources are unavailable.

### 2.3 Geophysical Modeling Layer

The Geophysical Modeling layer implements forward simulation and inverse estimation for multiple geophysical methods.

**forward**: This module generates synthetic geophysical data from physical property distributions. For electrical resistivity tomography, the module wraps PyGIMLi's finite element solver to compute apparent resistivity responses for arbitrary electrode configurations on two-dimensional or three-dimensional meshes. For seismic refraction tomography, the module implements eikonal-based travel time computation. For time-domain electromagnetic (TDEM) methods, the module interfaces with SimPEG to simulate transient responses for layered Earth models, enabling integration of airborne or ground-based electromagnetic data with hydrological simulations.

**inversion**: This module recovers subsurface property distributions from geophysical observations. The ERT inversion implements Occam-style smoothness-constrained inversion with options for L1 or L2 model regularization. Time-lapse inversion extends the single-time framework with temporal regularization, enforcing smoothness of property changes between successive measurement times while allowing for sharp spatial boundaries. A windowed time-lapse algorithm enables processing of long monitoring sequences by inverting overlapping temporal windows, reducing memory requirements while maintaining temporal continuity. Structure-constrained inversion incorporates velocity interfaces derived from seismic tomography as internal mesh boundaries, allowing discontinuous resistivity variations across lithological contacts. TDEM inversion utilizes SimPEG's optimization framework to recover layered conductivity profiles.

### 2.4 Integration Layer

The Integration layer provides high-level workflows that combine multiple modules for complete hydrological-geophysical analysis.

**Hydro_modular**: This module implements forward workflows from hydrological models to synthetic geophysical data. Given hydrological simulation outputs, the module chains petrophysical transformation with geophysical forward modeling to predict observable geophysical responses. This capability supports survey design optimization, sensitivity analysis, and validation of geophysical monitoring strategies against process-based hydrological predictions.

**Geophy_modular**: This module implements inverse workflows from geophysical observations to hydrological property estimates. Key functionality includes extraction of structural interfaces from seismic velocity tomograms for constraining ERT inversion, conversion of inverted resistivity distributions to water content with uncertainty quantification through Monte Carlo sampling of petrophysical parameters, and joint interpretation of multiple geophysical datasets. The Monte Carlo framework propagates uncertainty in petrophysical parameters (e.g., cementation exponent, surface conductivity) to derived hydrological quantities, providing confidence bounds on water content estimates.

## 3. Data Flow

The architecture supports three primary workflow patterns:

**Forward Modeling Workflow (HM → GM)**: Hydrological model outputs are loaded through `model_output`, interpolated to geophysical mesh coordinates via `core`, transformed to geophysical properties using `petrophysics`, and passed to `forward` to generate synthetic observations. This workflow enables prediction of geophysical responses from hydrological simulations.

**Inverse Modeling Workflow (GM → HM)**: Field geophysical data are imported through `data_processing`, inverted using `inversion` with meshes and regularization from `core` and numerical solutions from `solvers`, and transformed to hydrological properties via `petrophysics` within `Geophy_modular`. This workflow enables estimation of hydrological properties from geophysical measurements.

**Coupled Analysis Workflow**: Forward and inverse capabilities are combined for model validation, data assimilation, or uncertainty quantification. Hydrological predictions are compared against inverted geophysical observations, or synthetic studies assess the resolution and uncertainty of geophysical monitoring under realistic heterogeneity.

## 6. Design Principles

**Modularity**: Each module operates independently with well-defined inputs and outputs, facilitating unit testing, maintenance, and selective usage of package components.

**Extensibility**: Abstract base classes define interfaces for hydrological model readers (`HydroModelOutput`), inversion algorithms (`InversionBase`), and petrophysical models (`BaseVelocityModel`), enabling extension to new data sources or methodologies without modifying core code.

**Interoperability**: By building upon established community libraries rather than reimplementing fundamental algorithms, PyHydroGeophysX maintains compatibility with existing workflows and benefits from ongoing improvements in foundational packages.

**Reproducibility**: Result classes (`InversionResult`, `TimeLapseInversionResult`) encapsulate complete outputs including models, meshes, convergence history, and metadata, supporting serialization for archival and reproducible analysis.

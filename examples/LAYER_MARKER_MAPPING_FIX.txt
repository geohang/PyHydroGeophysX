================================================================================
LAYER MARKER MAPPING FIX - Para Domain to Layer Structure
================================================================================

Date: 2025-01-13
Issue: Para_domain markers were cell IDs, not layer markers for petrophysics

================================================================================
PROBLEM DISCOVERED
================================================================================

After first fix attempt, user reported:
  "[petrophysics] [INFO] Found 1 geological layers: [0]"
  "Both regolith and fractured_bedrock mapped to layer ID 0"

Debug logging revealed:
  Para domain markers: [0, 1, 2, ..., 4700] - 4701 unique cell IDs!
  Mesh with interface: [1, 2, 3] - Layer structure (2=regolith, 3=bedrock)

PyGIMLi assigns unique IDs to para_domain cells during inversion, completely
losing the layer structure from mesh_with_interface.

================================================================================
ROOT CAUSE
================================================================================

When ERTManager performs inversion:
1. Input: mesh_with_interface (5832 cells, markers: 1, 2, 3)
   - Marker 1: Background/padding cells
   - Marker 2: Regolith (above seismic interface)  
   - Marker 3: Fractured bedrock (below seismic interface)

2. Output: para_domain (4701 cells, markers: 0, 1, 2, ..., 4700)
   - Each cell gets a unique ID
   - Layer structure is LOST!

3. Problem: PetrophysicsAgent needs layer markers to apply different parameters

================================================================================
THE SOLUTION
================================================================================

Implemented spatial mapping from mesh_with_interface to para_domain using
nearest neighbor search:

1. Get cell centers from both meshes:
   - para_centers = para_domain.cellCenters()  # 4701 cells
   - mesh_centers = mesh_with_interface.cellCenters()  # 5832 cells

2. Build KD-tree for fast spatial queries:
   - from scipy.spatial import cKDTree
   - tree = cKDTree(mesh_centers)

3. For each para_domain cell:
   a. Find nearest mesh_with_interface cell
   b. Copy its layer marker (2 or 3)
   c. Map background (marker 1) to regolith (marker 2)

4. Result: para_layer_markers array (4701 cells with markers: 2, 3)

================================================================================
CODE CHANGES
================================================================================

File: PyHydroGeophysX/agents/structure_constraint_agent.py

Lines 261-305: Added layer marker mapping logic

```python
# Map layer markers from mesh_with_interface to para_domain
mesh_markers = np.array(mesh_with_interface.cellMarkers())
para_layer_markers = np.zeros(para_domain.cellCount(), dtype=int)

# Get cell centers
para_centers = para_domain.cellCenters()
mesh_centers = mesh_with_interface.cellCenters()

# Build KD-tree for nearest neighbor search
from scipy.spatial import cKDTree
tree = cKDTree(mesh_centers)

# Map each para_domain cell to nearest mesh cell's layer
for i in range(para_domain.cellCount()):
    para_center = para_centers[i]
    dist, idx = tree.query(para_center)
    mesh_marker = mesh_markers[idx]
    
    # Map: mesh marker 3 → para marker 3 (bedrock)
    #      mesh marker 1,2 → para marker 2 (regolith)
    if mesh_marker == 3:
        para_layer_markers[i] = 3
    else:
        para_layer_markers[i] = 2
```

Line 307: Save mapped markers to disk
Line 313: Return mapped markers in results['cell_markers']

================================================================================
WHY THIS APPROACH WORKS
================================================================================

1. **Spatial Consistency**: Para_domain cells are spatially close to their
   parent mesh_with_interface cells, so nearest neighbor mapping preserves
   layer boundaries accurately.

2. **Efficient**: KD-tree enables O(log N) nearest neighbor queries instead
   of O(N²) brute force search.

3. **Robust**: Works regardless of mesh refinement or cell count differences.

4. **Preserves Interface**: The seismic-derived interface boundary is
   maintained through spatial proximity.

TECHNICAL NOTES
================================================================================

** PyGIMLi Mesh Hierarchy **

constrained_mesh (mesh_with_interface)
  └─> Used for forward modeling (fine mesh)
      5832 cells with layer markers [1, 2, 3]
      
para_domain
  └─> Used for inversion (coarser, parameter mesh)
      4701 cells with unique IDs [0, 1, ..., 4700]
      Created from constrained_mesh by ERTManager

** Why Markers Get Lost **

ERTManager.paraDomain is created with:
- Simplified geometry for inversion
- New cell numbering (0, 1, 2, ...)
- No layer structure preservation

** Our Solution **

Use spatial mapping to reconstruct layer structure in para_domain
based on original mesh_with_interface layer boundaries.

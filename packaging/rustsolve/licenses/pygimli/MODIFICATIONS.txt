libgimli in this archive: pyGIMLi's core library, modified
==========================================================

pyGIMLi is Copyright (C) 2005-2024 by the GIMLi development team and is
licensed under the Apache License, Version 2.0 (COPYING.rst in this folder).
As section 4(b) of that licence asks, this notice states that the library
was built from modified files; each changed source file also carries a
notice under its licence header.

The modifications were made in 2026 by Hang Chen. Two scripts apply them:
pgcore/apply_rustsolve.py of rustsolve (https://github.com/geohang/rustsolve,
commit c83f4e9), which also supplies the replacement
pgcore/src/cholmodWrapper.cpp, and then
packaging/rustsolve/apply_notriangle.py of PyHydroGeophysX
(https://github.com/geohang/PyHydroGeophysX).

Sources the library was built from
-----------------------------------
Windows (libgimli.dll): gimli commit 5991b6ac, the source of pgcore 1.5.0 on
  the gimli conda channel; version string
  libgimli-v1.5.0-1-g5991b6ac+rustsolve+notriangle. Built with MSYS2 MINGW64
  GCC 16.2.0 by rustsolve's pgcore/build-libgimli-msys2.sh.
macOS (libgimli.dylib, arm64): gimli v1.5.4, commit 6241cfab, the source of

  libgimli-v1.5.3-53-g6241cfab+rustsolve+notriangle. Built with conda-forge
  clang 21.1.8 by rustsolve's pgcore/build-libgimli-macos.sh, in GitHub
  Actions run 39815917732 of geohang/PyHydroGeophysX.

Files changed by apply_rustsolve.py
-----------------------------------
CMakeLists.txt, core/src/CMakeLists.txt
    The GIMLI_RUSTSOLVE option. With it, the library links rustsolve's C
    interface (rustsolve_capi) instead of SuiteSparse CHOLMOD and UMFPACK,
    and its version string ends in "+rustsolve".
core/src/cholmodWrapper.cpp
    Replaced. The CHOLMOD and UMFPACK calls are replaced by calls to
    rustsolve (Cholesky, LDL^T and LU on the faer library).
core/src/cholmodWrapper.h
    Overrides of SolverWrapper's two setMatrix(const ...&) overloads. The
    class layout is unchanged.
core/src/linSolver.h, core/src/linSolver.cpp
    A matrix the solver refuses leaves no solver behind, and solve() then
    raises an error instead of using the previous matrix's solver; the
    previous solver and the cached matrix are freed; SolverWrapper's
    one-argument setMatrix overloads are implemented; the LDL solver type
    raises an error, since this build has no LDL library.
core/src/bert/dcfemmodelling.cpp
    The DC forward frees the solver it creates also when a factorization or
    solve raises an error. With topography, the primary potentials at the
    forward mesh's nodes are taken from the P2 mesh the forward makes for
    them (its first nodes are the forward mesh's) instead of being
    interpolated; a primary mesh set by the caller is still interpolated.

Files changed by apply_notriangle.py
------------------------------------
CMakeLists.txt
    Triangle is not looked for, so the library neither contains nor calls
    it; the version string gains "+notriangle".
core/src/triangleWrapper.cpp
    Without Triangle, every meshing call raises an error that names the
    rustmesh backend, instead of printing "Triangle not installed" and
    returning nothing. No exported symbol is removed.

Every other file is pyGIMLi's own and unchanged. This library contains no
Triangle code; PyHydroGeophysX's rustmesh backend makes the 2-D meshes (see
the rustmesh notice folder).
